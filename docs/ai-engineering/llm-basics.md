# 大模型与深度学习基础

做 AI 应用开发不要求能训练大模型，但面试常问“原理层”的问题：模型是怎么学的、Transformer 为什么有效、Embedding 是什么、什么时候该微调什么时候该用 RAG。这篇按这个顺序整理。

## 一、机器学习的基本概念

### 1. 三种学习范式

| 范式 | 训练数据 | 典型任务 |
| --- | --- | --- |
| 监督学习 | 有标签（输入 → 正确答案） | 分类、回归、文本分类 |
| 无监督学习 | 无标签 | 聚类、降维 |
| 强化学习 | 奖励信号 | 游戏、机器人、RLHF |

大模型的训练其实三种都用到了：预训练是**自监督**（用文本自身的下一个词当标签），指令微调是监督学习，RLHF 是强化学习。

### 2. 模型是怎么“学”的

一句话：**定义损失函数，用梯度下降让损失变小。**

1. **前向传播**：输入经过网络得到预测值
2. **计算损失**：衡量预测和真实值的差距。回归常用均方误差（MSE），分类常用交叉熵
3. **反向传播**：用链式法则算出损失对每个参数的梯度
4. **参数更新**：参数沿梯度反方向走一小步，`w = w - 学习率 × 梯度`

常见优化器：SGD、Momentum、Adam（大模型训练基本都用 Adam / AdamW）。

### 3. 过拟合与欠拟合

- **欠拟合**：训练集上都表现差，模型太简单或训练不够
- **过拟合**：训练集表现好、测试集表现差，模型“背答案”了

缓解过拟合的手段：

- 增加数据、数据增强
- 正则化：L1 / L2（权重衰减）
- Dropout：训练时随机丢弃部分神经元
- 早停（Early Stopping）：验证集指标不再提升就停
- 降低模型复杂度

### 4. 评价指标

分类任务不能只看准确率，样本不均衡时会误导。

- **精确率 Precision** = 预测为正的样本中真正为正的比例（“说对的有多少是真的对”）
- **召回率 Recall** = 真正为正的样本中被找出来的比例（“该找的找到了多少”）
- **F1** = 精确率和召回率的调和平均
- **AUC**：ROC 曲线下面积，衡量排序能力

> RAG 里的“检索召回率”就是 Recall 的思路：相关文档有没有被检索出来。

### 5. 常见网络结构

| 结构 | 特点 | 典型场景 |
| --- | --- | --- |
| MLP 全连接 | 最基础 | 表格数据、网络中的子模块 |
| CNN 卷积网络 | 局部感受野、权值共享 | 图像分类、目标检测（CV） |
| RNN / LSTM | 按时间步处理序列 | 早期 NLP、时序预测 |
| Transformer | 自注意力，可并行 | 大模型、NLP、多模态 |

RNN 的两个问题：只能串行计算、长距离依赖容易梯度消失。Transformer 就是为解决这两点而生的。

## 二、Transformer

### 1. 自注意力（Self-Attention）

核心思想：**序列里每个词都去“看”其他所有词，按相关程度加权汇总信息。**

每个词向量通过三个矩阵映射出 Q（Query）、K（Key）、V（Value）：

```
Attention(Q, K, V) = softmax(Q·Kᵀ / √d_k) · V
```

- `Q·Kᵀ`：每个词和其他词的相关度打分
- `/ √d_k`：缩放，防止维度大时点积过大导致 softmax 梯度过小
- `softmax`：把分数变成权重（和为 1）
- `· V`：按权重加权求和

**多头注意力（Multi-Head）**：并行做多组注意力，每组关注不同的关系（语法、指代、语义），最后拼接。

### 2. 其他关键组件

- **位置编码**：注意力本身不感知顺序，需要额外注入位置信息。原始论文用正弦余弦，现在的大模型多用 RoPE（旋转位置编码）
- **前馈网络（FFN）**：每个位置独立的两层全连接
- **残差连接 + 层归一化（LayerNorm）**：让深层网络能稳定训练

### 3. 三种架构

| 架构 | 代表 | 擅长 |
| --- | --- | --- |
| Encoder-only | BERT | 理解类任务：分类、抽取、Embedding |
| Decoder-only | GPT、Qwen、Llama、DeepSeek | 生成类任务，当前大模型主流 |
| Encoder-Decoder | T5、原始 Transformer | 翻译、摘要 |

### 4. 大模型是怎么生成文本的

**自回归**：每次只预测下一个 token，把它拼回输入，再预测下一个，直到输出结束符。

- **token**：模型处理文本的最小单位，中文大约一个汉字对应 1～2 个 token
- **采样参数**：`temperature` 越低输出越确定，越高越发散；`top_p` 只从累计概率前 p 的候选里采样
- **KV Cache**：已生成部分的 K、V 缓存起来，避免每一步重复计算，是推理加速的基础（见 [模型服务部署](/ai-engineering/model-serving)）

> 为什么大模型会“幻觉”？因为它本质是在预测“最可能的下一个词”，而不是在查询事实。训练数据里没有、或者有冲突的知识，它也会生成“看起来合理”的内容。

## 三、Embedding

### 1. 是什么

**把文本（或图片）映射成一个固定长度的向量，语义相近的内容向量也相近。**

```
"如何办理宽带"   → [0.12, -0.33, 0.81, ...]
"宽带怎么开通"   → [0.10, -0.30, 0.79, ...]   ← 距离很近
"今天天气不错"   → [-0.52, 0.44, 0.03, ...]   ← 距离很远
```

### 2. 相似度计算

- **余弦相似度**：比较方向，最常用
- **点积**：向量归一化后等价于余弦相似度
- **欧氏距离**：比较绝对距离

### 3. 在应用里的用途

- RAG 的语义检索
- 语义缓存（相似问题直接复用答案）
- 文本聚类、去重、推荐

常见中文 Embedding 模型：BGE 系列、M3E、各家大模型厂商提供的 Embedding API。

### 4. 双塔与交叉编码

| | Bi-Encoder（双塔） | Cross-Encoder（交叉编码） |
| --- | --- | --- |
| 方式 | 问题和文档分别编码成向量再比较 | 问题和文档拼在一起输入模型打分 |
| 速度 | 快，文档向量可以提前算好 | 慢，每对都要算一次 |
| 精度 | 一般 | 高 |
| 用途 | 召回（从海量文档里粗筛） | 重排（Rerank，对少量候选精排） |

这就是 RAG 里“先召回、再重排”的原因。

## 四、让大模型掌握新知识：Prompt、RAG、微调

### 1. 三种手段对比

| | Prompt 工程 | RAG | 微调（Fine-tuning） |
| --- | --- | --- | --- |
| 改变什么 | 输入 | 输入（注入检索到的资料） | 模型参数 |
| 适合 | 简单任务、格式约束 | 知识问答、知识频繁更新 | 固定风格、特定格式、专业领域能力 |
| 知识更新 | — | 改知识库即可，实时 | 需要重新训练 |
| 可解释性 | — | 能给出引用来源 | 差 |
| 成本 | 最低 | 中等（需要检索系统） | 高（数据、算力） |
| 幻觉 | 依赖模型本身 | 能显著降低 | 不能根治 |

### 2. 面试回答思路

> **RAG 解决“知道什么”，微调解决“怎么说、怎么做”。**
>
> 企业知识问答这类知识多、更新快、需要溯源的场景，优先用 RAG；需要模型学会特定的输出格式、语气或者领域推理方式时才考虑微调。两者也可以结合：先微调让模型更会利用检索结果，再用 RAG 提供实时知识。

### 3. 微调的常见方法

- **全参数微调**：更新所有参数，效果好但显存和算力成本高
- **LoRA**：冻结原模型，只训练低秩矩阵。原理是假设参数更新量 ΔW 是低秩的，用两个小矩阵 `B·A` 近似，可训练参数降到原来的千分之一量级
- **QLoRA**：在 4-bit 量化的模型上做 LoRA，单张消费级显卡也能微调 7B 模型

### 4. 大模型训练的三个阶段

1. **预训练**：海量无标注文本，学习语言和世界知识
2. **指令微调（SFT）**：用“指令 → 回答”数据，让模型学会听指令
3. **对齐（RLHF / DPO）**：用人类偏好数据，让回答更有用、更安全

## 五、高频面试题速记

1. **Transformer 相比 RNN 的优势？** 可以并行计算；自注意力直接建立任意两个位置的联系，长距离依赖更好。
2. **为什么要除以 √d_k？** 维度大时点积方差大，softmax 会进入饱和区导致梯度很小，缩放让训练更稳定。
3. **Embedding 和 one-hot 的区别？** one-hot 维度高、稀疏、无法表达语义相似；Embedding 低维、稠密、相近语义距离近。
4. **temperature 设为 0 意味着什么？** 每一步都选概率最高的 token（贪心），输出基本确定，适合问答、抽取类任务。
5. **大模型为什么有上下文长度限制？** 自注意力的计算量与序列长度的平方成正比，显存中的 KV Cache 也随长度线性增长。
6. **微调和 RAG 怎么选？** 见上文第四节。
