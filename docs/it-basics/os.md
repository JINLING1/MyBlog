# 操作系统

后端面试里的操作系统问题，核心都围绕“并发”：进程线程的区别、怎么同步、为什么死锁、为什么一个线程能处理上万连接。

## 一、进程、线程与协程

### 1. 三者的区别

| | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 定义 | 资源分配的基本单位 | CPU 调度的基本单位 | 用户态的轻量级“线程” |
| 资源 | 独立的地址空间、文件句柄 | 共享所属进程的资源，有自己的栈和寄存器 | 共享线程资源 |
| 切换开销 | 大（切换页表、刷新缓存） | 较小 | 极小，不进入内核 |
| 调度 | 操作系统 | 操作系统 | 程序自己（主动让出） |
| 隔离性 | 一个崩溃不影响其他 | 一个崩溃可能拖垮整个进程 | 同线程 |

**一句话：进程是“房子”，线程是房子里干活的人，协程是一个人在多件事之间灵活切换。**

协程的例子：Python 的 `async/await`、Go 的 goroutine、JavaScript 的 async 函数（基于事件循环）。适合**大量 I/O 等待**的场景，比如同时调用几十个外部 API、处理大量网络连接。

### 2. 进程的状态

```
新建 → 就绪 ⇄ 运行 → 终止
          ↑     ↓
          阻塞 ←
```

- 就绪：万事俱备，只等 CPU
- 运行：正在占用 CPU
- 阻塞：在等待 I/O 等事件，有 CPU 也跑不了

### 3. 进程间通信（IPC）

| 方式 | 特点 |
| --- | --- |
| 管道 | 单向，常用于父子进程（如 shell 里的 `ls \| grep`） |
| 消息队列 | 按消息收发，内核保存 |
| 共享内存 | 最快，但需要自己加锁同步 |
| 信号量 | 用于同步，不传数据 |
| 信号 | 异步通知，如 `kill -9` |
| Socket | 可以跨机器，最通用 |

### 4. 多进程和多线程怎么选

- **CPU 密集型**（计算、模型推理预处理）：多进程，能利用多核。Python 有 GIL，多线程无法并行执行字节码，要用多进程
- **I/O 密集型**（网络请求、读写数据库）：多线程或协程，等待期间可以切换去做别的事

## 二、线程同步

### 1. 为什么需要同步

多个线程同时修改共享数据会出错。比如两个线程同时执行 `count++`，这不是一个原子操作，而是“读取 → 加一 → 写回”三步，交错执行就会丢失更新。

### 2. 同步手段

| 手段 | 作用 |
| --- | --- |
| 互斥锁（Mutex） | 同一时刻只允许一个线程进入临界区 |
| 读写锁 | 读读可以并发，读写、写写互斥，适合读多写少 |
| 信号量（Semaphore） | 允许 N 个线程同时访问，常用于限制并发数（如连接池） |
| 条件变量 | 线程等待某个条件成立，配合互斥锁使用（生产者-消费者） |
| 原子操作 / CAS | 无锁，硬件保证“比较并交换”原子执行 |

### 3. 乐观锁与悲观锁

- **悲观锁**：认为一定会冲突，先加锁再操作。如 `synchronized`、数据库 `SELECT ... FOR UPDATE`
- **乐观锁**：认为很少冲突，不加锁，提交时检查有没有被别人改过。如 CAS、数据库版本号 `UPDATE ... WHERE version = ?`

读多写少用乐观锁，冲突频繁用悲观锁（乐观锁冲突多时会不停重试，反而更慢）。

## 三、死锁

### 1. 四个必要条件

同时满足才会死锁：

1. **互斥**：资源同一时间只能被一个线程占用
2. **占有并等待**：拿着一个资源，同时等待另一个
3. **不可抢占**：别人拿着的资源不能强行抢
4. **循环等待**：A 等 B，B 等 A，形成环

### 2. 怎么避免

破坏任意一个条件即可，实际中最常用：

- **按固定顺序加锁**（破坏循环等待）：所有线程都先锁 A 再锁 B
- **一次性申请所有资源**（破坏占有并等待）
- **加锁超时**（破坏不可抢占）：`tryLock(timeout)` 拿不到就释放已有的锁并重试

### 3. 怎么排查

Java 用 `jstack` 查看线程栈，会直接提示 “Found one Java-level deadlock”；数据库死锁可以查看死锁日志（MySQL `SHOW ENGINE INNODB STATUS`）。

## 四、内存管理

### 1. 虚拟内存

每个进程都以为自己独占一块连续的完整内存，实际上由操作系统把虚拟地址映射到物理内存。

好处：

- 进程之间相互隔离，一个进程不能访问另一个进程的内存
- 程序可以使用比物理内存更大的空间（不常用的页换出到磁盘）
- 简化编程，不用关心物理地址

### 2. 分页

虚拟内存和物理内存都按固定大小的“页”（常见 4KB）划分，通过**页表**记录映射关系。访问的页不在内存中时触发**缺页中断**，操作系统从磁盘调入。

页面置换算法：FIFO、LRU（最近最少使用，最常用）、LFU、Clock。

> LRU 也是 Redis 内存淘汰和各种缓存的常用策略，面试常让手写 LRU（哈希表 + 双向链表）。

### 3. 用户态和内核态

- 用户态：普通程序运行的状态，不能直接访问硬件
- 内核态：操作系统内核运行的状态，有全部权限

程序读文件、发网络请求时通过**系统调用**进入内核态，这个切换有开销。所以减少系统调用次数（批量读写、零拷贝）是常见的性能优化。

## 五、I/O 模型

### 1. 五种 I/O 模型

| 模型 | 过程 |
| --- | --- |
| 阻塞 I/O | 调用后一直等，数据就绪才返回 |
| 非阻塞 I/O | 没数据立刻返回，需要不断轮询 |
| I/O 多路复用 | 一个线程同时监听多个连接，哪个就绪处理哪个 |
| 信号驱动 I/O | 数据就绪时内核发信号通知 |
| 异步 I/O | 发起后不管，内核把数据拷好后通知 |

### 2. I/O 多路复用：select、poll、epoll

这是“一个线程处理上万连接”的关键，Nginx、Redis、Node.js 都基于它。

| | select | poll | epoll（Linux） |
| --- | --- | --- | --- |
| 连接数上限 | 1024 | 无 | 无 |
| 找出就绪连接 | 遍历所有，O(n) | 遍历所有，O(n) | 内核回调，直接返回就绪的，O(1) |
| 每次调用 | 要把整个集合拷贝到内核 | 同左 | 注册一次即可 |

epoll 的两种触发模式：

- **水平触发（LT）**：只要还有数据没读完，就一直通知。默认模式，编程简单
- **边缘触发（ET）**：只在状态变化时通知一次，必须一次读完。效率更高，需要配合非阻塞 I/O

## 六、高频面试题

1. **进程和线程的区别？** 见第一节表格，重点答资源和调度、开销、隔离性。
2. **线程切换为什么比进程快？** 同一进程的线程共享地址空间，不需要切换页表，CPU 缓存和 TLB 不会失效。
3. **死锁的条件和解决办法？** 四个必要条件；按顺序加锁、超时释放。
4. **Redis 单线程为什么快？** 纯内存操作；I/O 多路复用处理大量连接；单线程没有锁竞争和上下文切换。
5. **epoll 为什么比 select 高效？** 不用每次拷贝全部连接，不用遍历找就绪连接，没有连接数上限。
6. **什么是协程？适合什么场景？** 用户态调度的轻量级执行单元，切换开销极小，适合大量 I/O 等待的高并发场景。
